# Implemented v0.1 scope

The current candidate lets an administrator inspect a captured entity change,
follow its HA context links, save the available evidence and export a sanitized
bundle.

| Surface | Current behavior |
| --- | --- |
| Capture | Four normalized event kinds; enabled-kind and entity/domain filters apply before rolling retention |
| Timeline | Newest matching events first; panel filters by entity and kind; API also accepts context and a `since` timestamp |
| Explain | Parent-context links, same-context sequence and explicit gaps; no confidence score or timing-only correlation |
| Trace enrichment | Live lookup of retained automation/script traces, reduced to structural paths and outcomes |
| Saved incidents | Frozen window of events already captured; review works independently of the rolling buffer |
| Export | Sanitized ZIP with manifest, incident JSON, summary and SHA-256; no raw-export mode |
| Diagnostics | Aggregate capture and persistence-call counters, without evidence identifiers |

## Bounds

- Rolling capacity: 256–8,192 events; default 2,048.
- Rolling save interval: 5–60 seconds; default 10.
- Timeline API: 1–500 events per request; panel requests 100.
- Live explanation: up to 100 events; default 50.
- Saved incidents: 50 records, 500 events per record.
- Incident window: up to one hour on either side of the target; default 300
  seconds before and 60 after. Saving does not wait for future events.
- Trace projection: at most 200 structural steps.

An oversized incident is rejected instead of silently truncated. Rolling
retention evicts the oldest events. See [known limitations](known-limitations.md)
for persistence, trace-retention and evidence gaps.

## Outside v0.1

No host monitoring, crash dumps, anomaly detection, AI root-cause analysis,
Recorder replacement, automation modification, cloud telemetry or non-admin
access.

## Release acceptance

Implementation is not release acceptance. The
[alpha checklist](alpha-release-checklist.md) requires real-instance installation,
lifecycle, privacy, forensic workflow and performance checks against an exact
candidate SHA before the first tag.
