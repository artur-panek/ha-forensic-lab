## Fixes for incident reloads and review

This release fixes three issues found while reviewing the first alpha.

- **Incident writes during reload:** the integration now waits for an in-flight save or deletion before replacing its store. Requests queued behind that write are rejected once closing begins, rather than writing through an obsolete store.
- **Saved-incident review:** late responses no longer replace a newer selection, leave an old error visible, or clear the current loading state. Closing, reopening and deleting a review invalidate its pending request.
- **Script filtering:** a timeline filtered to `script.name` now includes direct calls to that script. Generic actions such as `script.turn_on` still match their captured targets.

The patches add six Home Assistant storage/lifecycle cases, ten frontend request-order cases and twelve script-query cases. They do not change the storage schema, retention settings, administrator requirements or panel layout.

### Update through HACS

Open **HA Forensic Lab**, enable **Show beta versions**, and select **v0.1.0-alpha.2** when updating or redownloading. Restart Home Assistant and refresh the browser tab. Keep the existing integration entry; no reconfiguration or data migration is required.

Take a Home Assistant backup before updating. The integration remains experimental and requires Home Assistant **2026.9.4 or newer**. Automated checks do not replace testing installation, restart and normal-use performance on a real instance.

Useful checks after updating: save an incident, reload the integration, review the saved incident, switch between two saved reviews, and filter the timeline to a directly called script. Report the release tag and HA version with any issue; review sanitized exports before sharing them.
